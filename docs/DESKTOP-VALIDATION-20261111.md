# 电脑端专项模拟验证（2026-11-11）

范围为现有浏览器 Web 工作台及其后端。本轮未开展微信实现或测试。桌面浏览器使用 Chromium，1440×1000；不代表所有浏览器兼容性认证。

## 发现并修复

在 Alice 的通知请求返回前退出并登录管理员，迟到的通知响应会显示到新账号页面。专项脚本用受控延迟、合成私有标记复现，修复前断言失败。现在每个 API 调用绑定发起时 token，返回时比较当前 token；不一致则拒绝处理。比较在处理 401 之前，因此旧账号的错误响应也不会清除新会话。

这修复客户端展示隔离，不涉及后端权限失效；后端仍核验请求所属身份。

## 本轮证据

| 场景 | 结果 |
| --- | --- |
| 迟到通知 + 退出／登录另一个账号 | 旧标记不出现在新账号页面 |
| 刷新页面 | 原有效会话恢复 |
| 普通用户／管理员桌面流程 | 登录、改期、取消、维护、占用日历、运营信息通过 |
| 内容转义 | 模拟设备描述中的 img 文本不生成图片元素 |
| 服务端提交后丢失 HTTP 响应 | 重试沿用原 requestKey，最终只有一条预约 |
| H2 / MySQL 8.4 | 各 50 项集成测试通过 |
| 双实例共享 MySQL，32 用户争用 | 1 确认、31 候补；幂等、越权、FIFO 通过 |
| 8 worker、2 设备、双实例、5 秒有界循环 | 281 次循环、32 次重放、0 错误、槽位释放 |
| 实际终止进程后重启 | 会话、真实审批截止、候补、通知、幂等恢复通过 |

短时负载不是最大吞吐或长时间稳定性证明。两台额外实例使用相同后端业务代码与隔离模拟 MySQL 数据；新增客户端隔离修复通过 8080 的重新构建实例验证。

## 复现与数据

```sh
CHROMIUM_PATH=/usr/bin/chromium node scripts/check-desktop-isolation.cjs
```

需要 Playwright、Chromium 和 demo 后端。可用 BOOKING_URL 修改服务地址；脚本使用 demo Alice/管理员账号，创建带随机后缀的模拟用户和设备，最后取消测试预约并停用设备，账号和审计记录保留。只在模拟环境运行。

该脚本复用 `booking_browser_check.js` 并显式传 `{mobile:false}`，不进入手机或微信测试。响应延迟／丢失使用 Playwright 拦截，但第一次写请求确实到达真实服务器并提交；不是只 Mock 成功结果。原始结果见 `docs/validation/desktop-*20261111.*`。

真实设备物理占用、真实用户试用、长时间稳定性、其他浏览器和生产部署仍未验证；本轮结果不代表不存在任何问题。
